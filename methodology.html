Evaluation Methodology & Fact Sheet

Every number on this page is read directly from a frozen evaluation dataset — nothing here is projected, adjusted, or rounded up. If a number on the main site links here, this is where it comes from.

Evaluation Basis

  • Measurement campaign conducted 2026-09-27 to 2026-09-28 against live Anthropic API endpoints (Claude Sonnet 5 and Claude Haiku 4.5), not a mock or simulated backend.
  • 438 total runs attempted, of which 355 were kept as clean, comparable measurements.
  • 83 runs excluded from the results: 74 were superseded/retired task-wording versions (a task prompt was revised mid-campaign, both old and new versions can't be mixed under one task id), 8 were a PII probe task intentionally excluded from savings numbers, and 1 was excluded for a cross-task answer contamination incident.
  • Task sizes span three bands — Small (light chat / status checks), Medium (Excel/PDF/invoice-scale documents), Heavy (SQL joins, directory scans, Parquet merges) — each run against both an unaided baseline and Opto, on both a cold cache and a warm cache, on both models.

Reduction Range, By Query Type

Opto's advantage is not a single number — it depends heavily on query size and whether the cache is warm. Per-query average reduction, unaided vs. Opto, across the six measured size/cache-state combinations:

SizeCacheToken ReductionCost Reduction
SmallCold80.2%79.1%
SmallWarm81.4%71.2%
MediumCold64.9%51.3%
MediumWarm67.8%14.3%
HeavyCold57.5%40.9%
HeavyWarm71.6%46.1%

Token reduction: 57.5% – 81.4%. Cost reduction: 14.3% – 79.1%. Cost reduction narrows on warm-cache Medium/Heavy queries because Anthropic's own cache discount already lowers the unaided baseline's price — Opto's token savings are still real and large there, they just translate into a smaller dollar gap once the baseline itself gets cheaper.

Your savings will depend on your own query mix. Small, repetitive, cache-friendly workloads see the largest reductions. Large one-off analytical queries against cold data see smaller ones. These ranges are the honest bounds from our own measured campaign — they are not a guarantee for any other workload. The only way to get a number specific to you is to run your own queries in the sandbox.
